# Ragmir

Ragmir is the open-source local retrieval and evidence layer for agentic RAG workflows.
Developer agents, scripts, and TypeScript applications consume precise project citations through
its library, CLI, or MCP server. The agent decides when to search, expand a citation, and refine
the query. It owns reasoning, generation, and actions, with the model chosen by the developer.
Forward deployed engineers and AI-native teams use it to ship RAG inside the environment that owns
the documents: a laptop for the first demo, then a VPS, an on-premise server, or an offline network.

## When a coding agent needs Ragmir

- A coding agent such as Claude Code or Codex can grep and read a few text files. grep matches only
  exact words and cannot search inside PDF or Office files, and the agent opens such files one at a
  time. Ragmir indexes more than 900 file types once (scans through optional local OCR) and cites
  each passage to its line, page, slide, sheet cell, or exported object.
- MCP search returns three compact citations by default, within a 32 KB output budget per call
  (`mcpMaxOutputBytes`), so the agent's context holds evidence instead of whole files, and only
  those excerpts and the passages the agent expands reach its model.
- One search takes up to five rewordings of the question (keywords, a paraphrase, a likely answer)
  fused into one ranking, names the question words that no indexed passage holds, and can match
  meaning with an optional local semantic model.
- When evidence is weak, search returns nothing, so the agent can say the documents do not cover
  the question. In Ragmir 6.5 benchmarks on three real bases, 68 of 90 off-topic questions
  returned nothing and no correct answer was refused.
- `rgr evaluate` measures retrieval on the team's own golden questions and fails a CI job below its
  thresholds.
- On a small code repository, the agent's own search is often enough, and grep remains the tool to
  list every occurrence or match a regular expression: Ragmir returns ranked passages.

## What teams shipping RAG get

- Any model: the index does not depend on the model that writes the answer, so a team can move
  between Claude, GPT, Gemini, Mistral, or a local model without re-indexing.
- Low running cost: default retrieval runs offline on the CPU, with no GPU, embedding API, API key,
  or vector database server; the index is an embedded LanceDB store under `.ragmir/`.
- Data residency: the index stays on the machine running Ragmir, in the country, cloud, and network
  the team chooses. Ragmir supports traceability (exact citations, explicit source selection with
  credentials left out, evaluation reports) but does not by itself make a system compliant with
  GDPR or the EU AI Act, and is not legal advice.
- Frameworks: TypeScript, LangChain.js, Python, LangChain and LangGraph, LlamaIndex, MCP, and the
  CLI read the same index and return the same citations.
- System requirements: Node.js 22.12 or later on Linux (x64 or ARM64), macOS, or Windows, or Docker
  on amd64 and arm64. `local-hash` needs no model. Semantic models need, to index, at least
  0.75 GB of memory for `mxbai-embed-xsmall-v1` (97 MB download), 1 GB for Granite R2 (124 MB),
  1.5 GB for `multilingual-e5-small` (492 MB), and 4 GB for `Qwen3-Embedding-0.6B` (624 MB);
  twice that memory and two CPUs is comfortable, and `rgr models list` checks the machine. A GPU is
  optional. Local OCR makes the first ingest of scanned documents slow, which is expected; its
  cache spares later ingests.

## Core facts

- Install `@jcode.labs/ragmir`; use the `rgr` executable. Node.js 22.12 or later is required.
  Linux, macOS, and Windows are tested on every release.
- Set up with `rgr setup --no-ingest`, add selected source directories with `rgr sources add`,
  then run `rgr ingest` and `rgr search "query" --compact`.
- Default local-hash retrieval needs no model, API key, or network. It ranks BM25 keyword evidence
  first, including source paths and camelCase identifier parts, and uses hashed vectors for ties.
- Semantic retrieval requires the optional `@huggingface/transformers` peer and a local model.
  Use `rgr setup --semantic` to configure and preload one. Default installs exclude that runtime.
  `ingestEmbeddingDevice: "webgpu"` embeds ingestion batches on the GPU, with a CPU fallback.
  `rgr models list` shows the known models and their fit for the machine; setup installs the
  recommended one (multilingual Granite R2 97M on most machines) unless the config names a model.
  Also supported: `mxbai-embed-xsmall-v1` (English), `multilingual-e5-small`,
  `multilingual-e5-base`, and `Qwen3-Embedding-0.6B` (its query instruction and last-token pooling
  apply, but it indexes eight times slower than Granite R2). EmbeddingGemma is not supported as a
  local model; `embeddingProvider: "openai-compatible"` with `embeddingEndpoint` embeds through
  Ollama, vLLM, or any OpenAI-compatible endpoint instead (opt-in: passage text goes to that
  endpoint).
- More than 900 extensions and file names index with no extra install: PDF, Office (macro-enabled
  files and templates, with chart titles, series, and values), OpenDocument (flat files too), EPUB,
  FictionBook, HTML and saved .mhtml pages, code in over 250 languages, C++ and Perl modules,
  Gherkin and Robot Framework tests, Visual Studio, MSBuild, and WiX projects, Godot scenes,
  configuration, XML property lists, translations, and build files such as Dockerfile,
  Jenkinsfile, go.mod, or meson.build. Text files keep their encoding
  (UTF-16 BOM, Windows-1252 fallback). Exports are cited object by object
  (`:section=Table%20INVOICE`): Figma .fig files and REST exports, Sketch, Excalidraw, tldraw,
  Obsidian canvases, XMind maps per sheet, .eml/.emlx/.msg mail decoded with attachment names, .mbox mailboxes per
  message, Evernote notes, Postman and Insomnia requests, HAR captures with cookies and
  credentials left out, OpenAPI and AsyncAPI operations, PowerDesigner, ERwin, MySQL Workbench,
  Oracle Data Modeler, draw.io, Visio, BPMN, DMN, ArchiMate, UML XMI, Tableau, GeoJSON features,
  and SARIF findings. `rgr audit --unsupported` reports gaps.
  Do not claim universal binary support.
- Paths are stored and cited with forward slashes and in Unicode NFC on every platform, so
  exclusions also match accented names stored decomposed. `rgr audit` reports source rules that
  match nothing and excluded files whose copy is still indexed.
- Local PDF OCR runs only on blank pages. `rgr ocr doctor` checks prerequisites and `rgr ocr setup`
  configures the engine; `--images` and `--legacy-word` add photo OCR and `.doc` extraction.
  Page caches and bounded batches avoid repeated work.
- Citations use source lines only when valid; transformed formats use pages, slides, cells, or
  EPUB spine coordinates. Indexed content is not masked or paraphrased.
- Markdown passages carry their heading path. Front matter stays one passage; its `title` roots a
  page without a level-1 heading, and `ragmir_sources` lists each page's title and description.
  `ragmir_expand` adds a Markdown page's outgoing links (broken ones with `path: null`) and the
  pages linking to it; `ragmir_sources` with `outline: true` returns one document's sections with
  their first citations. Links navigate; they are not evidence. `rgr audit --knowledge` (or
  `ragmir_audit` with `knowledge: true`) audits Markdown pages read-only: broken links, missing and
  unlinked pages, duplicate titles, written citations that changed, and stale declared sources.
  `ragmir_sources` with `changedSince` lists the files changed since a time.
- MCP exposes five read-only tools (`ragmir_status`, `ragmir_search`, `ragmir_expand`,
  `ragmir_sources`, `ragmir_audit`), `ragmir_ingest` to refresh the index incrementally, the
  `answer`, `compile-source`, and `audit-knowledge` prompts, and bounded `ragmir://context` and
  `ragmir://sources` resources. Search starts with three
  compact citations, accepts up to five related queries in one budget, filters by folder or glob
  (`**/*.pdf`), and returns passages already seen in the session as short stubs. Excerpts start at
  the lines holding the question's words (`excerptLine`), results carry `pathContext` from
  `pathContexts` or scope descriptions, and a notice names question words no passage holds
  (`absentTerms` in `searchReport()` and `--json`). `searches` adds up to five formulations of one
  question, fused with it into one ranking: `lex` keywords (`"phrase"` required, `-word`
  excluded), a `vec` paraphrase, or a `hyde` passage written as the answer might read (`--lex`,
  `--vec`, `--hyde` in the CLI). Expansion returns `nextCitation` to read a
  document through and accepts up to five `citations` at once. A scope with
  `searchByDefault: false` is searched only by name. `ragmir_ingest` writes only the private index and
  refuses with `mcpIngest: false` or while `rgr security-audit` warns. Instructions name the base;
  unrelated workspaces get a scope notice, or a refusal with `mcpAllowedRoots`. Register Ragmir per
  project, not for every project.
- Results carry `sourceStatus` when the cited file changed after indexing and `weakEvidence` when
  support is thin. An empty answer means the base holds no evidence for the question.
  `rgr doctor` checks freshness on every run; `rgr hooks install` refreshes the index after Git
  operations.
- Agents search, expand selected evidence, and refine queries. Ragmir does not run the agent loop.
- Present four workflow examples: build a feature and diagnose an incident with Claude Code or Codex
  using cited project evidence; ground an AI product in customer documents with the LangChain.js
  retriever, which returns no passage when the documents are silent; then make a confidential
  architecture decision with a local or self-hosted chat. Local and self-hosted are model
  deployment choices within the confidential workflow.
- Personal corpora work the same way: research notes and past transcripts for a YouTube script,
  a lifetime of paperwork (bank statements, payslips, certificates) prepared with a local model
  such as Ollama, or a whole career history matched against job offers. Indexing and search stay on
  the machine; the model the user connects decides where cited excerpts go.
- Use one `createRagmirClient()` per project root in a long-running process and close it at shutdown.
  Top-level functions serve one-shot scripts. Ragmir opens no HTTP port.
- Servers: Ragmir runs on a VPS, an on-premise server, a CI runner, or a Debian or Alpine container
  as a non-root user with a read-only root filesystem and no network. Point `storageDir` (or
  `RAGMIR_STORAGE_DIR`) at a persistent volume and run `rgr ingest` from a scheduled job. The host
  service owns TLS, authentication, per-user authorization, and rate limits; Ragmir does not filter
  results per user. Writers are serialized per machine, not across machines.
- Docker: `ghcr.io/jcode-works/ragmir` runs the same CLI and MCP server without Node.js; mount the
  project at `/workspace` and pass `--user "$(id -u):$(id -g)"` on Linux. `:full` adds the semantic
  model runtime and local Tesseract OCR. Releases tag `X.Y.Z`, `X.Y`, `X`, and `latest`, plus
  `-full` variants, for amd64 and arm64 with SBOM and provenance attestations.
- Python 3.11+: `pip install ragmir` gives a typed client (`Ragmir` sync with async twins,
  `AsyncRagmir`) that keeps one MCP server per project; `init_project`, `add_sources`, and
  `run_cli` prepare a base. `langchain-ragmir` adds `RagmirRetriever` and `RagmirToolkit` for
  LangChain and LangGraph; `llama-index-retrievers-ragmir` adds a LlamaIndex `RagmirRetriever`.
  The client runs the project's npm install, a global `rgr`, the matching npm release through
  npx, or the `ghcr.io/jcode-works/ragmir` image when Node.js is absent. `langchain-mcp-adapters`
  is unmaintained; prefer `langchain-ragmir`.
- Agent plugins from this repository, each with the MCP server (Claude Code, Codex, and Cursor also
  bundle the retrieval and indexing skills): Claude Code (`/plugin install ragmir --marketplace
  jcode-works/ragmir`, then `/ragmir:index`), OpenAI Codex (`codex plugin marketplace add
  jcode-works/ragmir`, then `codex plugin add ragmir@ragmir`), Cursor (`plugins/ragmir`),
  Gemini CLI (`gemini extensions install https://github.com/jcode-works/ragmir`), and Qwen
  Code (`qwen extensions install jcode-works/ragmir:ragmir`). Plugins need local files, so they run
  in coding agents, not in web or mobile chat apps.
- Agent Skills: `npx skills add jcode-works/ragmir` installs five skills from `skills/`
  (listed on skills.sh): `ragmir` (cited retrieval loop), `ragmir-setup` (install, sources, index,
  agent connection, OCR, semantic model, upgrades), `ragmir-build` (TypeScript, LangChain.js,
  Python, LlamaIndex, Docker), `ragmir-evaluate` (golden files, `rgr evaluate` gates, tuning), and
  `ragmir-wiki` (a cited Markdown wiki compiled from sources and linted with the knowledge audit).
- LangChain.js: `RagmirRetriever` from `@jcode.labs/ragmir/langchain` (optional peer
  `@langchain/core` 1.x) returns LangChain documents whose `metadata` holds the citation, and an
  empty array when the sources hold no evidence. `createRagmirTools({ client })` (or
  `RagmirToolkit`) gives `createAgent` and LangGraph agents `ragmir_search` and `ragmir_expand`
  tools that answer with cited text and keep documents as the tool artifact.
- The MCP Registry lists the server as `io.github.jcode-works/ragmir`, with the npm package and
  the Docker image.
- Coding assistants that fetch library documentation find Ragmir on Context7 as
  `/jcode-works/ragmir`, refreshed from this repository after each release.
- Monorepos select the nearest configured base; inspect `rgr bases` and use `--project-root` to
  target one explicitly. Data resolves from the caller's project, never the installation directory.
- Ingestion is bounded and resumable. Rebuilds stage a replacement and activate it atomically only
  after validation, preserving the last valid index on failure. An index built before the keyword
  terms stays searchable until the next `rgr ingest` or `rgr upgrade` rebuilds it.
- After updating, run `rgr upgrade --check`, then `rgr upgrade` when needed. Retired configuration
  keys are explicitly migrated with a private backup; old masking-policy indexes need rebuilding.
- `rgr preview`, `rgr evaluate`, `rgr doctor --deep`, `rgr audit`, and `rgr storage optimize` support
  source inspection, retrieval quality, live diagnostics, and index maintenance.
- Optional ingestion metrics are local counters and timings, without source content or raw queries.
- Keep `.ragmir/` and credentials out of Git. Share reviewed sources normally, then ingest locally.
- Settings in project config files that run a program (OCR and extractor commands), send data off
  the machine (a remote `embeddingEndpoint`, any `embeddingApiKeyEnv`, model downloads), or read
  outside the project stay inactive until approved on each machine with `rgr trust` (`--yes` in
  CI, or `RAGMIR_TRUST_PROJECT_CONFIG=1`). Embedding calls fail with `UNTRUSTED_CONFIG` before any
  request; Git hooks and MCP never approve. `RAGMIR_*` environment overrides need no approval.
- The index stays on the machine running Ragmir. The consuming application decides where
  unmasked passages go: a local model, a self-hosted server (including private cloud), or a provider.
  Local indexing and self-hosting alone do not guarantee confidentiality. Control the client,
  model endpoint, access, transport, and logs; a cloud provider’s data policy applies to sent content.
- AGPL-3.0-only from v3.0.0, with separate commercial licensing from JCode Works. Earlier releases
  keep their original license. No accounts, activation, hosted storage, or cloud OCR.
